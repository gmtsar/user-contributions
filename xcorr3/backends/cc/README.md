# xcorr_cc

[中文](README.zh-CN.md)

CUDA/cuFFT implementation of GMTSAR-style amplitude cross-correlation for SAR
image registration and pixel offset tracking. It reads two GMTSAR PRM/SLC pairs
and writes sampled range/azimuth offsets. Geocoding is optional.

## Dependencies and installation

- Linux, an NVIDIA GPU and compatible driver, CUDA Toolkit with `nvcc`/cuFFT.
- Make, a CUDA-compatible C/C++ compiler, `pkg-config`, GLib development headers.
- For `-geocode`: GMT, GMTSAR (`proj_ra2ll.csh` in `PATH`), C shell, and a matching
  `trans.dat` generated by GMTSAR. Correlation alone does not need these.

From this source directory (Ubuntu/Debian example; install CUDA separately):

```sh
sudo apt install build-essential pkg-config libglib2.0-dev
make                         # CUDA in /usr/local/cuda
# For system CUDA in /usr/bin, use: bash build_local.sh
mkdir -p "$HOME/.local/bin"
install -m 755 xcorr_cc "$HOME/.local/bin/xcorr_cc"
export PATH="$HOME/.local/bin:$PATH"   # Add to your shell startup file to persist
```

Override the GPU architecture if needed, e.g. `make CUDA_ARCH=sm_75` for the
RTX 2070 SUPER. For other CUDA locations, set `CUDA_HOME` or the Makefile's
`CUDA_NVCC`, `CUDA_INC` and `CUDA_LIB`. Local regression environment: CUDA 12.0,
RTX 2070 SUPER, Ubuntu 24.04 under WSL2.

## Usage examples

Run in a directory where the SLC paths recorded in both PRMs resolve:

```sh
# Correlation only; preserves PRM coarse shifts
xcorr_cc master.PRM secondary.PRM -nx 20 -ny 50 -xsearch 128 -ysearch 128

# Optional geocoding for an already aligned pair; matching trans.dat required
xcorr_cc master.PRM aligned.PRM -nx 40 -ny 100 -xsearch 128 -ysearch 128 \
  -noshift -geocode -snr 18 -psnr 5

xcorr_cc --help
```

Choose sampling, windows and filtering for your data; these are starting points.
`-noshift` ignores PRM coarse shifts and should only be used deliberately.

| Option | Default | Purpose |
|---|---|---|
| `-nx N`, `-ny N` | 16, 32 | Number of range/azimuth samples |
| `-xsearch N`, `-ysearch N` | 64, 64 | Search radii; powers of two, at least 8 with subpixel interpolation |
| `-range_interp N`, `-interp N` | 2, 16 | Range / subpixel interpolation factors; range factor must be a power of two |
| `-norange`, `-nointerp` | Off | Disable the respective interpolation |
| `-noshift` | Off | Ignore PRM `rshift`/`ashift` |
| `-geocode` | Off | Filter, grid, convert to metres and geocode |
| `-snr N`, `-psnr N` | 10, 5 | Geocoding correlation / peak-significance thresholds |
| `-no_blockmedian` | Off | Grid directly, without median processing |

`freq_xcorr.dat` contains six columns:
`x_pixel x_offset y_pixel y_offset correlation peak_snr`.
Offsets are in pixels; correlation is on a 0–100 scale. `-geocode` also produces
`azi_offset.grd`, `rng_offset.grd` and their `*_offset_ll.grd` geographic grids
in metres. The integrated range conversion uses **minus** the pixel offset.

This does not cover all GMTSAR `xcorr` modes: CPU time-domain and grid-input modes
are unsupported, and CUDA/CPU results can differ. Check the exit code: input,
output or requested geocoding failures return nonzero. Results are staged before
publication; detected publication failures trigger rollback. Use one job per
output directory; multi-file publication is not crash-atomic.
See [regression tests](test/README.md).
